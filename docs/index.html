Can We Identify Content at Risk of Declining?

Using machine learning to prioritize content pages for human review based on measurable search and content-performance signals.

01 · Abstract

What was this project trying to answer?

This project asks whether observable search and content-performance signals can identify pages associated with declining performance early enough to help content teams prioritize human review. Using an anonymized 30,000-row content-performance slice from the FlyRank ML Internship dataset, I trained a Random Forest classifier using impressions, CTR, average position, content age, and time since last update. On the evaluated client-grouped test split, the model achieved 0.680 Precision@50, compared with 0.440 for the Week 4 baseline. A 5-fold client-grouped validation produced a mean Precision@50 of 0.768, although performance varied across client groups. The result provides directional evidence that machine learning can help prioritize pages for investigation, while the final decision about what to change remains with a human reviewer.

02 · Introduction

The content problem behind the model

Content teams can have many pages competing for limited attention. The challenge is not simply finding pages that are performing poorly; it is deciding which pages should be investigated first.

A simple rule can provide a starting point, but content performance depends on several signals at once. A page can have substantial visibility but weak engagement, an unfavorable average position, increasing age, or a combination of these factors.

This capstone explores whether a machine-learning model can combine these signals to create a more useful prioritization queue than a simple ranking rule.

Research question: Can we identify content that is at risk of declining early enough to prioritize which pages should receive attention?

The goal is therefore not to automatically rewrite or refresh content. Instead, the model is treated as a decision-support layer that can help a content team decide where human investigation should begin.

03 · Data

This analysis uses the FlyRank ML Internship dataset, release flyrank_pseudonymized_warehouse_release_v20260703. The release is based on anonymized production search and content-performance data.

For this capstone analysis, I worked with the provided content_refresh_anonymized.csv slice containing 30,000 content items. Each row represents a pseudonymized content item with observed search and engagement metrics, content metadata, freshness information, and derived comparison-window fields.

Public-safety choices

The analysis uses pseudonymized identifiers only where needed for grouping and validation. Client IDs and content IDs were not used as model features.

The published analysis contains no client names, domains, URLs, page titles, keywords, or raw search queries. Product decision flags and composite decision scores were also excluded so that the model was based on observable signals rather than reproducing an existing product decision.

Time-window context

The model features include pre-aggregated 90-day performance measures such as impressions_90d and ctr. The analysis therefore works from the supplied comparison-window fields rather than reconstructing individual daily records in the 30,000-row slice.

The broader FlyRank release contains production warehouse tables; this capstone page reports the results from the public-safe anonymized analysis slice actually used in the model.

04 · Methodology

How the model was built

Model

I used a Random Forest classifier because it can capture nonlinear relationships and interactions among multiple content-performance signals without requiring those relationships to be linear.

Target label

The target was created from the observed trend_direction field:

  • 1 = trend_direction is "down"
  • 0 = otherwise

Features

The final model used five observable features:

  • impressions_90d — recent search visibility
  • ctr — click-through rate
  • avg_position — observed search position
  • content_age_days — content age
  • days_since_last_update — freshness signal

Baseline

The Week 4 baseline ranked pages using a simple combination of recent visibility and CTR opportunity. The Random Forest was evaluated against this baseline using the same client-grouped test split and the same Precision@50 metric.

Validation design

The primary evaluation used an 80/20 client-grouped split with random_state = 42. Pages from the same client were kept entirely within either the training or test set. This avoids placing pages from the same client on both sides of the evaluation.

I then strengthened the evaluation using 5-fold client-grouped cross-validation. This checks whether the single-split result is reasonably stable across different groups of clients.

Leakage checks

I audited the final feature set for three potential forms of leakage:

Label-derived features

Features that directly encode the target were excluded. The target itself was not used as a model feature.

Future or overlapping information

Performance measures were reviewed because they could potentially overlap with the period used to define the observed trend.

Decision-derived features

Existing product decision flags and composite scores were not used as model inputs.

Important caveat

The timeline relationship between some 90-day performance features and the observed trend label requires verification. Results are therefore presented as directional.

06 · Limitations

What this analysis cannot claim

A useful model is not the same thing as proof of causality. This analysis identifies patterns associated with observed declining performance; it does not establish that any feature causes a decline.

Not a causal model

A high feature importance does not mean changing that feature will improve a page's performance.

Not a guarantee of future decline

The label describes an observed trend in the available data. It should not be interpreted as guaranteed future performance.

Limited analysis sample

The model was developed using the provided 30,000-row anonymized content slice rather than independently training on the full production warehouse.

Timeline caveat

Some 90-day performance features may overlap with the period used to define the observed trend label. This requires further timeline verification.

Honest framing: The measured results provide directional evidence that the model may be useful for ranking pages for human review across unseen client groups. They should not be presented as guaranteed predictive performance or evidence that model-driven content changes will improve search performance.
07 · Ranked Recommendations

What should a content team do with the result?

1

Prioritize high-scoring pages for human review

Use the model score to create a ranked review queue rather than treating every page equally. Higher-scoring pages can be investigated first because the model associates them more strongly with the observed declining label.

Action: Review the highest-priority pages first and investigate the signals behind their ranking.

2

Investigate visibility and ranking signals

impressions_90d and avg_position were the two strongest model features. Pages showing weak recent visibility or less favorable observed ranking should therefore receive closer investigation.

Action: Check whether the page remains relevant, aligned with search intent, and strategically important before deciding on an intervention.

3

Review content age and freshness alongside performance

content_age_days was the third strongest model feature. Older content may deserve additional attention when it also shows other signals associated with decline.

Action: Check whether information is outdated or whether a refresh is warranted, but do not use age alone as an automatic refresh trigger.

Human-review workflow

Rank → Investigate → Review → Decide → Act

The model should function as a prioritization layer, not as an automated content decision-maker.

What should not be automated: The model should not automatically publish or rewrite content, delete pages, make redirects or canonical changes, or override editorial judgment.
