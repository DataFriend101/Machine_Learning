Can We Identify Content at Risk of Declining?

A decision-support approach for prioritizing content pages for human review using observable search and content-performance signals.

Abstract Introduction Data Methodology Results Limitations Recommendations Reproducibility Data Credit

Abstract

This study asks whether observable content-performance signals can be used to identify pages associated with declining performance early enough to prioritize human review. The analysis uses a 30,000-row anonymized content-performance slice from the FlyRank ML Internship dataset and evaluates five observable features: recent impressions, CTR, average position, content age, and days since the last update. A Random Forest classifier was compared with a simpler visibility-and-CTR baseline using Precision@50 and client-grouped validation. On the evaluated Week 5 client-grouped test split, the Random Forest achieved measured Precision@50 of 0.680 compared with 0.440 for the baseline, while 5-fold client-grouped validation produced a mean of 0.768. The resulting model is intended as decision support for prioritizing pages for human investigation, not as a causal model or an automated content-change system.

1. Introduction / Problem Statement

Content teams often have more pages to review than they can investigate manually. A practical challenge is deciding which pages deserve attention first when performance signals suggest that a page may be declining.

The decision supported by this analysis is therefore: which pages should a content team prioritize for human review?

A simple rule can provide a starting point, but content performance is influenced by several signals at once. This case study evaluates whether a machine-learning ranking approach can provide higher measured Precision@50 than a simpler baseline while using only observable, public-safe signals.

Decision framing: The model is designed to answer "which pages should we look at first?" rather than "what change should we automatically make?"

2. Data

This analysis uses the FlyRank ML Internship dataset, release flyrank_pseudonymized_warehouse_release_v20260703. The underlying release is based on anonymized production search and content-performance data.

For this project, the analysis uses the provided content_refresh_anonymized.csv slice rather than directly querying or exporting additional production data. The slice contains 30,000 rows, with one row representing a pseudonymized content item. It includes observed search and engagement metrics, content metadata, age/freshness fields, and derived comparison-window fields.

Public-safety treatment

The provided slice contains no client names, domains, URLs, page titles, keywords, or raw search queries. Pseudonymized client_id and content_id values were used only for grouping and validation and were not used as model features.

The analysis uses the observable signals included in the approved anonymized slice. Product decision flags and composite product scores were not used as model inputs.

Time and comparison windows

The analysis uses the precomputed performance fields provided in the anonymized slice, including 90-day comparison measures such as impressions_90d. The capstone does not reconstruct or export additional production date windows from the warehouse.

Scope: The results are based on the 30,000-row anonymized slice used throughout the internship analysis. They should not be interpreted as results from a complete client-level production deployment.

3. Methodology

Model choice

I used a Random Forest classifier because it can capture nonlinear relationships and interactions among multiple content-performance signals without requiring those relationships to be linear.

Features

The final model uses five observable features:

impressions_90d ctr avg_position content_age_days days_since_last_update

Pseudonymized identifiers were excluded from the model features and used only for client-grouped validation.

Label definition

The target is_declining_label was created from the observed trend_direction field:

1 = trend_direction == "down"
0 = otherwise

The positive rate in the full dataset was 54.2%. This label represents an observed performance trend in the available data; it is not treated as proof of future decline or as a causal outcome.

Baseline

The Week 4 baseline ranked pages using a simple combination of recent visibility and CTR opportunity. The Random Forest was evaluated against this baseline using the same test split and the same Precision@50 metric.

Validation design

The primary Week 5 evaluation used an 80/20 client-grouped split with random_state=42. Pages from the same client were kept entirely within either the training or test set, providing a more realistic test of generalization to unseen clients.

The analysis was subsequently strengthened using 5-fold client-grouped cross-validation. The same Random Forest configuration was evaluated across five client-grouped folds to reduce dependence on a single train/test split.

Leakage checks

The final feature set was audited for three potential forms of leakage: label-derived features, future or overlapping time information, and decision-derived features.

Feature Leakage assessment
impressions_90d Potential overlap with the period used to define the observed trend; timeline requires verification.
ctr Potential overlap with the label period; timeline requires verification.
avg_position Potential overlap with the label period; timeline requires verification.
content_age_days No obvious leakage identified.
days_since_last_update No obvious leakage identified.

Because the timing of some performance features relative to the observed trend label requires further verification, the findings are presented as measured and directional rather than causal or guaranteed predictive performance.

5. Limitations & Honest Framing

This analysis identifies patterns associated with observed declining performance. It does not establish that any feature causes a decline or that changing a feature will improve performance.

The analysis uses the provided 30,000-row anonymized content slice rather than the full FlyRank production warehouse. The findings should therefore be treated as directional and may not generalize to every client, content type, or search environment.

The 5-fold client-grouped validation provides a stronger assessment than relying on a single split, but performance still varied across client groups. In addition, the timing relationship between some performance features and the observed trend label requires further verification.

Finally, a high model score does not guarantee that an intervention will improve performance. The model should therefore support human prioritization rather than automatically determine content changes.

Claim boundary: These results are observed and measured on this dataset. They provide directional evidence for a decision-support workflow; they do not prove causal impact or guaranteed performance on future clients.

6. Ranked Recommendations

1. Prioritize high-scoring pages for human review

Use the model score to create a ranked review queue rather than treating every page equally. Pages with higher scores can be reviewed first because the model identifies them as having a stronger association with the observed declining label.

Action: Review the highest-priority pages first and investigate the signals behind their ranking.

2. Investigate visibility and ranking signals

impressions_90d and avg_position were the two strongest model features. Pages showing weak recent visibility or less favorable observed ranking should therefore receive closer investigation.

Action: Review whether the page remains relevant, aligned with search intent, and strategically important before deciding on an intervention.

3. Review content age and freshness alongside performance

content_age_days was the third strongest model feature. Older content may deserve additional attention when it also shows other signals associated with decline.

Action: Check whether information is outdated or whether a refresh is warranted, but do not use age alone as an automatic refresh trigger.

Human-review rule

Rank → Investigate → Review → Decide → Act

The model should function as a prioritization layer. Final decisions remain with a human reviewer.

What should not be automated

  • Automatically publishing or rewriting content.
  • Automatically deleting pages.
  • Automatically making redirects or canonical changes.
  • Overriding editorial judgment solely because of a model score.
